#+title: Symac feature mine: lost-rob0t/dotfiles
#+startup: overview

* Purpose

This document is the compatibility and inspiration inventory mined from the
actual Emacs/Doom configuration in =lost-rob0t/dotfiles=.

It is intentionally behavior-first.  Package names are evidence of desired
capabilities, not requirements to clone Emacs implementations.

* Literate configuration is a core UX requirement

The source config is Org-first: canonical Org files generate executable config.
Symac should preserve that style without requiring Emacs Lisp.

Required behavior:

- human-readable literate configuration is authoritative;
- generated configuration is reproducible;
- generated/configured state can be checked for drift;
- package declarations and behavior config can be separated;
- source ownership is explicit;
- platform profiles may share code without pretending their constraints are
  identical;
- configuration reload should be safe and observable.

Target Symac package:

- =symac-literate-config=

Distribution integration:

- =symac-distribution=

Tests:

- deterministic compile/tangle;
- source/generated parity;
- changed source causes expected generated diff;
- invalid config fails without partially mutating running state;
- reload leaves previous good config active on failure.

* Doom-style distribution UX

The desktop config depends heavily on the benefits of an opinionated
distribution even though Symac libraries themselves should stay neutral.

Mined behaviors:

- coherent module/package enablement;
- leader-key discoverability;
- quick navigation;
- popups/temporary window policy;
- modeline/status information;
- workspaces;
- project-aware commands;
- helpful defaults without preventing replacement;
- terminal and graphical operation;
- theme switching;
- consistent command naming.

This belongs to the Symac distribution, not low-level editor core.

* Prompt library

The existing prompt library accepts multiple formats and normalizes them into a
common record.

Observed formats:

- Org;
- Markdown;
- declarative Lisp;
- legacy raw prompt files.

Observed metadata concepts:

- id;
- title;
- description;
- tags;
- aliases;
- body;
- source path;
- format.

Symac should make this a native library with parser and validation protocols.

Target system:

- =symac-prompt-library=

Acceptance requirements:

- no evaluation required to read declarative prompt data;
- format parsers normalize into one typed prompt object;
- malformed metadata produces a useful condition;
- duplicate IDs are detected;
- aliases are indexed;
- prompt records are reloadable without restarting Symac.

* Fail-closed approval workflow

The dotfiles contain a research approval flow with unusually strong invariants.

Mined behavior:

- canonical approval fields;
- reject dirty repositories;
- reject detached HEAD;
- reject ambiguous upstream;
- verify exact base commit/blob;
- dry-run push before mutation;
- show narrow diff;
- explicit human confirmation;
- file-only commit;
- never guess/create branch;
- failed push leaves recoverable verified local state.

This is valuable as a generic workflow/approval package.

Target packages:

- =symac-approval=
- =symac-git-approval=

Tests must include every fail-closed branch.

* Durable agenda synchronization

The config asynchronously syncs saved Org agenda files while protecting editor
responsiveness and concurrent state.

Mined behavior:

- save hook dispatches asynchronous sync;
- exact saved contents are snapshotted;
- shared lock protects concurrent local/timer sync;
- remote fast-forward and local restore are explicit;
- conflicting edits fail closed;
- recovery copy retained;
- periodic timer and editor save share synchronization primitive.

Target package:

- =symac-org-sync=

This package should use a generic sync protocol so Git is one backend.

* Android/Termux

The real config deliberately separates three environments:

- full desktop development;
- Termux development profile;
- lightweight native Android reader/client.

Symac should preserve this principle.

Required architecture:

- shared runtime protocols;
- frontend abstraction;
- terminal frontend;
- desktop frontend;
- Android frontend;
- Termux/native process integration;
- low-resource/mobile profile;
- full mobile development profile.

Feature parity tests must never assume desktop GUI availability.

* What is explicitly not the goal

- transliterating Emacs Lisp into Common Lisp line-for-line;
- making Symac core depend on StarIntel;
- making Org mandatory for users who do not want it;
- making one completion UI mandatory;
- tying models to one provider;
- tying graph execution to a Python runtime;
- hiding package behavior behind untestable global startup magic.
